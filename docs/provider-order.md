# 模型供应商分类与排序

供应商页按 Claude Code、Codex 分类，使用各自的本地图标。删除原有“连接 / 官方账号”标签；官方登录和已有 API 连接都在所属 Agent 分类中管理。

## 排序和默认

- 连接行左侧手柄支持指针拖动，上下按钮和手柄的 Alt + ↑ / ↓ 提供键盘替代。搜索时先清空搜索再排序，避免移动隐藏的连接。
- 每个 Agent 保存独立完整顺序，第一项为该 Agent 新聊天默认。默认 Agent 仍由聊天设置控制。
- 模型菜单的供应商筛选和模型分组遵循同一顺序；当前聊天的模型只显示选中标记，不会改变分组位置。
- 明确选过连接的草稿及已有聊天保留自己的模型。排序不调用模型、不压缩上下文，也不重启运行中的 Agent。
- “保存为默认”和官方账号启用会把对应连接移到第一位。新增导入追加，改名和重复导入保留原有位置。删除默认连接后顺延到下一项；绑定聊天的连接仍不能直接删除。
- 官方账号使用 CLI 的原生认证。原来使用本机 CLI 配置的用户保留对应入口及既有默认。

## 持久化

Rust 在 SQLite settings 中保存 `connection_order_claude` / `connection_order_codex`，只保存连接 ID。排序和默认选择在一个事务里更新，继续同步兼容的 `profile_*` / `official_*` 设置。

旧数据首次迁移时把原默认连接置于首位，其余保持原列表顺序。已有会话 connection_id、model、native_id 不被排序操作修改。重启保留排序。过时列表、重复 ID、跨 Agent ID 或缺失连接的排序请求被拒绝，失败不会写入部分结果。

Rust 测试覆盖旧数据迁移、重启保存、默认变更只影响新聊天、运行中聊天原生绑定保留、非法请求原子拒绝、导入追加、改名不移动、删除顺延及官方默认。
