## 内存样本

发布版启动后、尚未启动 Agent、空工作区的一次测量：

| 范围 | 工作集合计 | 私有工作集合计 |
| --- | ---: | ---: |
| 应用及全部 WebView2 子进程 | 602.5 MiB | 246.7 MiB |
| 其中 SuperCode 主进程 | 79.4 MiB | 30.9 MiB |

最终窗口尺寸下，添加当前项目与一个空会话后再次测量：进程组工作集合计 630.3 MiB，私有工作集合计 249.7 MiB，尚未启动 Agent。

供应商设置重做后的发布版，打开已有 Claude 历史与设置页时，一次样本为工作集 747.2 MiB、私有工作集 386.0 MiB；主进程私有工作集约 32.1 MiB，其余主要是 WebView2。该次没有 Agent 子进程。样本保存于 `.supercode/settings-final-memory.json`；与空工作区样本场景不同，未据此宣称内存下降。

2026-10-07 客户端功能完善后的最终发布版，打开已有 Claude 历史和真实模型菜单时，进程组工作集 732.7 MiB、私有工作集 361.5 MiB；其中主进程私有工作集 31.1 MiB。没有 Agent / 工具子进程，样本位于 `.supercode/client-final-memory.json`。WebView2 仍占主要部分，不将不同场景的样本差异称为优化收益。

这些是本机样本，不是固定内存上限。工作集含共享页，跨进程相加会重复计算共享部分；私有工作集不包括共享页，也不等于整个进程组给系统造成的全部额外开销。界面资源面板显示工作集。

真实集成测试中，关闭全局 MCP 后 Agent 与工具进程的工作集约 208–212 MiB；开启原有全局 MCP 配置时一次样本约 1123 MiB。不同工具、会话和机器会影响数值。

可复现发布版进程组测量：

```powershell
./scripts/measure-memory.ps1 -SuperCodeProcessId <SuperCode进程ID>
```

本阶段已采用按需启动、空闲释放、MCP 开关、分页历史、输出限制和按需加载组件。WebView2 仍是空闲内存的主要来源，后续需要继续优化。
