# 对话刻度高光

2026-10-07。

用户要求白色刻度对应当前查看的轮次。通过 computer-use 实际操作 Codex 桌面客户端，观察了滚动、刻度预览、点击预览定位与返回最新位置：每条用户消息有一个刻度；滚动改变当前高光；预览其他轮次时保持原高光，预览刻度仅变宽。这里只复现观察到的行为，没有读取或声称知道 Codex 的内部算法。

SuperCode 的真实对话复现了五轮但高亮第四轮的问题：第五轮已经显示，旧实现仍等待这一轮经过视口顶部 70px 处才更新。

## 实现

- 从已经载入的用户轮次生成刻度，工具记录和模型切换标记不单独计数。
- 用聊天视口中部的阅读位置识别当前轮次；滚到底部时识别可见的最后一轮，包含短回复与小数像素位置。
- 高光绑定轮次 ID。加载更早历史时，序号随历史增加，仍对应同一轮内容。
- 滚动、视口尺寸变化、各轮内容高度变化都通过合并后的 animation frame 重新计算。观察器、监听器和未完成的回调在卸载时清理。
- 内容高度变化包含流式回复、Markdown 延迟加载、执行详情展开和字体或窗口变化；不依赖下一次滚动才更新。
- 点击定位将所选轮次的问题放入阅读区域，不将整段长回复居中。高光来自实际浏览位置，平滑定位期间随画面移动。
- 长历史在滚动中重新排版时，会在动画停稳后重新核对目标位置并平滑校正，最多三次、五秒。用户手动滚动、触摸、再次点击或按键时取消校正，不拉回用户；卸载与切换历史时清理回调。不强制展开全部历史内容。
- 单击刻度直接定位，不需要双击或再次点击预览。键盘焦点和悬停打开预览；预览只影响预览展开状态，不修改当前高光。非当前刻度是灰色，当前刻度使用主题文字颜色。

`npm run build` 与 `cargo test --manifest-path src-tauri/Cargo.toml` 通过，Rust 81 项。
