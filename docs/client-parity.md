## 2026-10-09：连续对话、排队、侧边聊天与托盘悬停

Agent 回复后保留可复用的连接，在同一会话、连接、模型与权限下继续下一轮。Claude 保留 JSONL 输入进程；Codex 复用 app-server，并记录已加载的会话，避免重复恢复；OpenCode / Pi 保留原生进程和会话。空闲约五分钟后释放，接收输出期间更新活动时间。切换 Agent、连接、模型或权限时按相应协议重新配置或重启。界面区分启动与思考，任务开始后不再持续显示“正在连接”。

Agent 工作时输入框可继续输入，并把待发消息放在输入框上方。消息支持编辑、删除、暂停和继续排队；附件、技能、模型与权限随消息保存。数据库按顺序发送，并为每条消息提供稳定的用户消息 ID。失败、停止和应用重启会保留并暂停待发消息，由用户继续发送，避免重复执行。每个会话最多保存二十条，全局最多二百条。

引导按底层 Agent 的实际能力执行：Codex 使用带当前任务 ID 校验的 `turn/steer`。后续协议审计修正了 Claude / OpenCode 的停止后重发实现，Claude 改为原生流式补充；本机 OpenCode 1.18.23 使用已验证的并行 `session/prompt`，其他未验证版本保留“停止并引导”。Pi 使用带 `streamingBehavior: "steer"` 的原生 `prompt`，兼容请求到达时刚好结束上一轮的情况。审批和提问继续通过原来的请求卡片交给用户。能力、版本边界和验证依据见 [Agent 输入协议审计](agent-input-capabilities.md)。

待发消息菜单增加“在侧边聊天中打开”，打开时暂停原消息；用户发送侧边消息后才移除原待发消息。选中回复文字显示“添加到对话 / 更多详情 / 在侧边聊天中提问”。侧边聊天按需加载，保存为独立会话，可在侧栏和独立窗口中继续查看。当前仍采用全局同时运行一个 Agent 任务的调度：主任务正在运行时，侧边提问会排队，并在主任务完成后发送；这是当前与 Codex 的多任务行为仍存在的差异。

托盘菜单失去焦点时先等待短暂间隔；鼠标仍位于菜单内时保持显示，离开并点击外部后收起。悬停“打开的窗口”可直接展开窗口列表，主题和紧凑尺寸沿用现有设置。
