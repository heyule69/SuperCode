# 系统通知优化

更新：2026-10-08。

## 使用方式

设置 → 通知集中管理总开关、提醒时机、任务类型、声音与隐私。默认提醒未查看的任务，当前正在查看的对话保持安静；也可选择只在应用后台提醒或始终提醒。关闭总开关不会清除已经选择的通知类型和声音。

通知分为任务完成、运行失败、等待确认。默认只显示提醒类型与打开应用的提示；开启“显示项目与任务名称”后才展示名称。通知不会带出对话正文、工具输出、命令或凭据。应用仍在运行时，点击通知会显示主窗口并打开对应对话。通知没有代替用户审批的操作。

页面读取 Windows 的实际通知状态并提供手动刷新。按用户要求移除整个“通知示例”区域，包括示例切换、预览卡片、说明、“发送测试通知”和系统通知设置入口；设置选项采用单列，填满页面内容宽度。系统勿扰和用户的横幅设置仍由 Windows 控制。

## 实现

- 任务通知由 Rust 运行时在成功保存事件后触发，不依赖前端接收到事件，也不会因多个聊天窗口监听事件而重复触发。
- 完成通知以保存事件前的会话及运行轮次校验：旧轮次、重复完成、用户停止不会误报完成。审批提醒读取实际等待状态，已处理的请求不会继续弹出。
- 每个会话、轮次和通知类型去重。内存记录最多 256 项，24 小时过期；提示音由系统通知播放一次。
- 前端保存偏好并通过 IPC 同步到 Rust；多个窗口通过本机 storage 事件同步。当前查看的对话及设置状态单独同步，结合原生窗口焦点判断是否需要提醒。
- Windows 使用真实应用标识 `dev.supercode.desktop`，注册本应用的名称和本地图标；不写系统的通知授权设置。原生点击事件发送 `notification-open` 给主窗口。已归档或移除的目标会提示去归档中查找。
- 不注册进程退出后的 COM 激活服务。当前点击返回能力的验证范围是 SuperCode 仍在运行时；macOS/Linux 的通知显示保留原插件实现，本轮没有验证其点击返回能力。

通知实现参考 [Tauri 通知说明](https://v2.tauri.app/plugin/notification/)、[Microsoft 应用标识说明](https://learn.microsoft.com/en-us/windows/win32/shell/appids) 和 [原生 Toast API](https://docs.rs/tauri-winrt-notification/latest/tauri_winrt_notification/struct.Toast.html)。

## 验证

新增测试覆盖偏好迁移、非法选项回退、默认隐藏任务名称、关闭总开关后保留选择、通知时机、去重上限、旧轮次与中止处理，以及通知文本过滤。前端 126 个测试、Rust 121 个测试、发布构建和 184 个文本文件的 UTF-8 无 BOM 检查通过。

Windows 发布版实际打开了通知页：真实系统状态为“系统允许发送通知”，总开关、三种类型、提醒时机、声音与名称选项、预览、底部滚动均显示正常。“发送测试通知”调用原生 Windows Toast 成功，页面显示“测试通知已提交系统”。本轮没有启动真实 Agent 消耗模型额度；自动化接口未提供可操作的通知横幅窗口，因此没有宣称完成横幅点击返回的端到端验证。
