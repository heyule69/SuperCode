# 用量、额度与平台图标

2026-10-07，按已确认设计及后续指导实现。

## 页面

- **用量**是独立设置分类：时间与 Agent 筛选、总 Token / 输入 / 输出 / 缓存、每日趋势、按模型或对话分组。点击日期筛选明细，点击条目查看细分。费用仅使用 Agent 返回的数据，不用套餐额度估算费用。
- **额度**是另一设置分类：左侧列出全部已保存连接、启用的官方账号与使用中的本机连接，点击后右侧仅展示该连接的额度窗口、重置时间或 API 余额。列表支持搜索。
- 查询失败或平台未提供接口时，保留连接入口并说明暂无可读取数据；不显示虚构的零额度。输入框下方额度入口仍只在实际取得数据时显示。
- 平台 HTTP 查询只在 Rust 侧进行，使用现有官方 HTTPS 适配；界面不接收密钥。只加载当前页面，只查询选中连接。Codex 官方额度优先复用匹配客户端，否则通过短暂账号连接读取后释放，不启动聊天，见 [官方额度读取](official-quota.md)。

## 模型切换

官方 Claude 文档说明模型切换保留对话，压缩主要用于上下文接近容量；Codex 的模型覆盖和压缩也是独立操作。实现采用如下规则：

1. 同一连接存在原生会话时，保留原生 ID，下一轮使用所选模型。上下文由原生 Agent 管理。
2. 跨连接不能依赖供应商特有的工具 / 思考块兼容性，因此交接标准化的对话、工具记录、附件路径和已有摘要。完整交接数据不超过 32 KiB 时直接保留，不另行调用模型压缩。
3. 超过这个保守的交接预算，或有条数、字节、单条消息截断时，先调用当前连接生成摘要；成功后再原子切换，失败保留旧连接和历史。
4. `/compact` 仍明确执行摘要压缩。原始聊天记录始终保留，切换边界准确显示“上下文已保留”或“上下文已压缩”。连续切换且没有新增历史时不重复压缩。

32 KiB 是可移植历史的保守字节预算，不是目标模型的精确 Token 上限。第三方网关没有统一可靠的上下文容量元数据，当前不伪称已自动识别各家实际容量。

来源：[Claude Code 的模型、用量及限制](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code)、[Claude 模型配置](https://code.claude.com/docs/en/model-config)、[Codex App Server](https://developers.openai.com/codex/app-server)。
