# 任务切换时的闪白与渲染器退出

## 已修正

- 原有主题同步只更新 Windows 标题栏和边框，WebView2 的内容底色仍来自固定的浅色配置。现在 `set_window_colors` 同时设置原生窗口和 WebView 的不透明内容底色，标题栏继续使用自己的主题颜色。
- `theme-init.js` 在页面解析时、React 和完整样式加载前恢复本机保存的主题。暗色、石墨、暖色和跟随系统均有对应的初始画布颜色，页面恢复时不先渲染浅色主区。
- React 中的字体和主题偏好在绘制前应用；页面、根节点和窗口底层使用一致的颜色。
- 保留原有任务状态、流式文字渐显、对话刻度动画和有次数限制的崩溃恢复机制。

WebView2 的默认背景色及早初始化是微软文档说明的防止加载闪白方式，见 [DefaultBackgroundColor](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2controlleroptions.defaultbackgroundcolor)。本次没有修改系统、显卡、全局 WebView 参数或无障碍能力。

### 第二次诊断：已定位内部断言

从微软符号服务器读取与本机 DLL 精确匹配的公共符号（PDB GUID `FDD2CAED8533508F4C4C44205044422E`，age 1），只下载必要的文件区间，转储保留在本机。冷分支 `+0x4dd5fd2` 检查 `eax == 2`，不满足时在 `+0x4dd5fdb` 执行 `int3`；正常分支返回 `+0x1cbc76e`，对应 `blink::AXBlockFlowIterator::PreviousOnLineAsIndex`。最新转储的 `rax=1`、`rcx=0`，热分支在读取文本片段的布局对象后跳入该检查。

这与对应 Chromium 154.0.8037.98 源码 `AXBlockFlowData::ComputeNeighborOnLine` 的 `CHECK_EQ(it->Type(), FragmentItem::kGeneratedText)` 一致：普通文本片段失去了布局对象，无障碍布局遍历触发内部断言。见 [对应版本源码](https://github.com/chromium/chromium/blob/154.0.8037.98/third_party/blink/renderer/modules/accessibility/ax_block_flow_iterator.cc#L150)。确切断言路径已经定位，哪次页面变更留下了失效片段仍需通过应用侧验证界定。

第二版在应用侧减少可避免的布局对象销毁：

- Markdown 的链接、行内代码、代码块使用稳定组件类型，通过 Context 更新事件处理函数；流式增量、任务完成和渐显收尾不再因内联组件函数身份变化而整体卸载这些节点。
- 对话正文不再使用 `content-visibility:auto`，避免在频繁更新和滚动时自动移除屏幕外的文本布局。消息分页、动画状态上限和组件缓存继续限制工作量。
- 不禁用无障碍功能，不更改系统或全局 WebView 设置，保留文字渐显效果及必要的页面恢复提示。

该改动是围绕已定位断言的应用侧缓解，不能把它等同于修复了 Chromium 本身。
